MTC test certificates
=====================

Merkle Tree Certificate (MTC) test certificates used by `test/mtc_cert_test.c`
and `test/mtc_verify_test.c`.  They target
draft-ietf-plants-merkle-tree-certs-06 and use the early experimentation OIDs
(for example `1.3.6.1.4.1.44363.47.0` for id-alg-mtcProof), not the
not-yet-assigned standard OIDs.  In an MTC certificate the signatureValue
carries the MTCProof; there is no signature over the TBSCertificate.

Well-formed (generated)
-----------------------

Generated by the demo tool of the draft's repository,
<https://github.com/ietf-plants-wg/merkle-tree-certs> (`demo/`, version
`plants-06`), for a 10-entry log 1 of the CA 32473.1, with ML-DSA-44 cosigners
32473.0, 32473.1 (the CA cosigner) and 32473.2.  Entry 0 is an intermediate CA
and entry 1 the leaf; landmark 1 is at tree size 8.  Each file is a
`CERTIFICATE PROPERTIES` block followed by the certificate.

- `mtc-leaf.pem` — leaf with a signatureless proof over the subtree [0, 10).
- `mtc-ica.pem` — intermediate issued by the MTC CA, also signatureless over
  [0, 10).
- `mtc-landmark.pem` — landmark-relative leaf, proving into the landmark 1
  subtree [0, 4).
- `mtc-leaf-standalone.pem` — standalone leaf over [0, 10), one CA cosignature
  (cosigner 32473.1).
- `mtc-leaf-standalone-3cosigners.pem` — three ascending cosignatures
  (32473.0, 32473.1, 32473.2).
- `mtc-leaf-standalone-no_ca_signer.pem` — one cosignature that is not the CA
  cosigner's (parses; rejecting it is a verification-time concern, not a
  parsing one).

Malformed cosignature lists (generated)
---------------------------------------

The MTCProof parses, but the cosignature list violates the section 6.2 ordering
rules, so `ossl_mtc_proof_get_cosignatures()` rejects it.

- `mtc-leaf-standalone-cosigner_wrong_order.pem` — cosignatures out of order.
- `mtc-leaf-standalone-duplicate_ca_signer.pem` — duplicate cosigner_id.

Malformed MTCProof (derived)
----------------------------

Derived from `mtc-leaf-standalone.pem` by, respectively, adding a byte to and
dropping a byte from its MTCProof and re-wrapping the enclosing DER (valid to do
because the signatureValue is opaque, with no signature over the TBS).
`ossl_mtc_proof_parse()` rejects both.

- `mtc-leaf-standalone-trailing.pem` — an extra trailing byte after the proof.
- `mtc-leaf-standalone-truncated.pem` — the proof's final byte removed.
