=head1 NAME

CRYPTO_secret_check_enable, CRYPTO_secret_check_disable
- control the check of private keys and seeds for encodings that are not
key material

=head1 SYNOPSIS

 #include <openssl/crypto.h>

 int CRYPTO_secret_check_enable(void);
 int CRYPTO_secret_check_disable(void);

=head1 DESCRIPTION

When a private key or seed is loaded, imported or set from bytes supplied
by the caller, OpenSSL checks its fixed-width encoding for structure that
key material does not have and that an identifier, string, handle,
counter or fill pattern stored in its place does have. The check rejects
an encoding if any of the following holds:

=over 4

=item *

the top 72 bits of its domain are zero, read as either a big-endian or a
little-endian integer; for a seed the domain is all of its bits;

=item *

at least a quarter of its bytes are zero, and never fewer than 16;

=item *

fewer than a quarter as many distinct byte values occur as there are
bytes, capped at 64 distinct values;

=item *

the bytes repeat with a period of 4, 8, 16 or 32, where at least 9 bytes
are compared.

=back

A uniformly chosen value of 13 bytes or more fails one of these with
probability below 2^-70. The check detects small integers, padded or
shifted handles and fill patterns; it does not detect text that fills
the field, a hashed or pseudo-randomly derived value, nor an opaque
full-width blob, and it makes no claim about randomness.

The check applies to EC, RSA private exponent, DSA, X25519, X448,
Ed25519, Ed448, ML-DSA, ML-KEM and SLH-DSA private keys and seeds. It is
not applied to keys generated by OpenSSL itself, to RSA factors, or to DH
private keys.

A rejected key fails to load with the reason B<ERR_R_SECRET_NOT_KEY_MATERIAL>.

CRYPTO_secret_check_enable() enables the check for the whole process and
CRYPTO_secret_check_disable() disables it. The check is enabled initially
unless OpenSSL was configured with B<no-secret-check>.

=head1 RETURN VALUES

CRYPTO_secret_check_enable() and CRYPTO_secret_check_disable() return 1 on
success and 0 on failure.

=head1 NOTES

Test suites that deliberately use degenerate keys, such as a private key
of 1 or an all-zero seed, should call CRYPTO_secret_check_disable() before
loading them. Disabling the check in production code removes a defence
against a key reference or identifier being mistaken for a key.
