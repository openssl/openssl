=head1 NAME

SSL_get_verify_result - get result of peer certificate verification

=head1 SYNOPSIS

 #include <openssl/ssl.h>

 long SSL_get_verify_result(const SSL *ssl);

=head1 DESCRIPTION

SSL_get_verify_result() returns the result of the verification of the
X509 certificate or raw public key presented by the peer, if any.
I<ssl> B<MUST NOT> be NULL.

=head1 NOTES

SSL_get_verify_result() can only return one error code while the verification
of a certificate can fail because of many reasons at the same time. Only
the last verification error that occurred during the processing is available
from SSL_get_verify_result().

Sometimes there can be a sequence of errors leading to the verification
failure as reported by SSL_get_verify_result().
To get the errors, it is necessary to setup a verify callback via
L<SSL_CTX_set_verify(3)> or L<SSL_set_verify(3)> and retrieve the errors
from the error stack there, because once L<SSL_connect(3)> returns,
these errors may no longer be available.

The verification result is part of the established session and is restored
when a session is reused.

When a server accepts an empty client Certificate message, the result is
X509_V_ERR_UNSPECIFIED. This applies to X.509 certificates and raw public
keys, during the initial handshake as well as subsequent requests for
client authentication. No credential verification is performed for an empty
response. The handshake can still complete if client authentication is optional.

=head1 BUGS

In other cases where no peer credential was presented, the returned result
can still be X509_V_OK, for example when a server did not request a client
certificate during the initial handshake. This means that no verification
error was recorded, not that the peer was authenticated.
SSL_get_verify_result() is only useful in connection with
L<SSL_get_peer_certificate(3)> or L<SSL_get0_peer_rpk(3)>.

=head1 RETURN VALUES

The following return values can currently occur:

=over 4

=item X509_V_OK

No verification error was recorded. A peer credential might not have been
presented; see L</BUGS>.

=item X509_V_ERR_UNSPECIFIED

An unspecified verification error occurred, or the server accepted an empty
client Certificate message.

=item Any other value

Documented in L<openssl-verify(1)>.

=back

=head1 SEE ALSO

L<ssl(7)>, L<SSL_set_verify_result(3)>,
L<SSL_get_peer_certificate(3)>,
L<SSL_get0_peer_rpk(3)>,
L<openssl-verify(1)>

=head1 HISTORY

Reporting X509_V_ERR_UNSPECIFIED for accepted empty client Certificate
responses was introduced in OpenSSL 4.1. Previously, accepting such a response
during an initial handshake returned X509_V_OK.
