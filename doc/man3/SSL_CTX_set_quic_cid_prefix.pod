=head1 NAME

SSL_CTX_set_quic_cid_prefix
- set a prefix for QUIC Connection IDs

=head1 SYNOPSIS

 #include <openssl/ssl.h>

 int SSL_CTX_set_quic_cid_prefix(SSL_CTX *ctx,
                                 const unsigned char *prefix,
                                 size_t prefix_len);

=head1 DESCRIPTION

SSL_CTX_set_quic_cid_prefix() configures I<ctx> so that every QUIC Connection
ID (CID) generated by connections created from it begins with the specified
I<prefix> of I<prefix_len> bytes.

When a prefix is set, the internal CID generator (LCIDM) fills each new CID
with random bytes and then overwrites the leading I<prefix_len> bytes with
I<prefix>.  The remaining bytes stay random, ensuring uniqueness within the
same worker process.

I<prefix_len> must be strictly less than the CID length (default 8 bytes)
and must not exceed B<QUIC_MAX_CONN_ID_LEN> (20).  If I<prefix> is NULL
and I<prefix_len> is 0, no prefix is applied and CIDs are fully random
(the default behaviour).

=head1 NOTES

This function is intended for multi-process QUIC servers that share a UDP
port via B<SO_REUSEPORT> and an eBPF routing program.  Each worker process
sets a unique prefix (e.g. derived from its PID) and registers that prefix
in a BPF map.  The eBPF program extracts the first bytes of the Destination
Connection ID from incoming packets and routes them to the correct worker.

This approach requires only one BPF map entry per worker process, regardless
of the number of active connections.  It is the same technique used by the
nginx QUIC implementation.

The prefix must be set before any QUIC connections are created on the
context.

=head1 RETURN VALUES

SSL_CTX_set_quic_cid_prefix() returns 1 on success or 0 on failure.
Failure occurs if I<prefix_len> is greater than or equal to the CID length,
or greater than B<QUIC_MAX_CONN_ID_LEN>.
