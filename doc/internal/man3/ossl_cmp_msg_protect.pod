=head1 NAME

ossl_cmp_calc_protection,
ossl_cmp_msg_protect,
ossl_cmp_msg_add_extraCerts
- functions for producing CMP message protection

=head1 SYNOPSIS

 #include "cmp_local.h"

 ASN1_BIT_STRING *ossl_cmp_calc_protection(const OSSL_CMP_CTX *ctx,
                                           const OSSL_CMP_MSG *msg);
 int ossl_cmp_msg_protect(OSSL_CMP_CTX *ctx, OSSL_CMP_MSG *msg);
 int ossl_cmp_msg_add_extraCerts(OSSL_CMP_CTX *ctx, OSSL_CMP_MSG *msg);

=head1 DESCRIPTION

ossl_cmp_calc_protection() calculates the protection for the given I<msg>
according to the algorithm and parameters in the message header's protectionAlg
using the credentials, library context, and property criteria in the I<ctx>.

When I<ctx->unprotectedSend> is set,
ossl_cmp_msg_protect() adds any configured extra certificates and returns
without setting protectionAlg or calculating protection. Otherwise,
ossl_cmp_msg_protect() (re-)protects the given message I<msg> using an algorithm
depending on the available context information given in the I<ctx>.
It uses the preferred I<ctx->protectionAlg> if set. Otherwise, it selects
PBMAC if there is a I<ctx->secretValue>, or signature-based protection if
there is a protection cert and key. The credentials required by the selected
algorithm must be available, or protection fails. For signing, it uses the cached
I<ctx->prot_sig_md> when I<ctx->protectionAlg> is set, or I<ctx->digest> otherwise.
The digest is irrelevant in the case of Edwards curves.
After successfully protecting the first message,
it remembers the selected algorithm in I<ctx->protectionAlg> for reuse in
subsequent request messages in the current transaction. With signature-based
algorithms, it also caches I<ctx->digest> in I<ctx->prot_sig_md> if the digest
is non-NULL. This ensures consistency if I<ctx->digest> changes later during
the transaction. Caching avoids having to determine the digest from
I<protectionAlg>, which can be difficult in some cases.

ossl_cmp_msg_add_extraCerts() adds elements to the extraCerts field in I<msg>.
It uses I<msg-E<gt>header-E<gt>protectionAlg> to determine whether protection is
signature-based. If so, and both I<ctx->cert> and I<ctx->pkey> are set,
it adds first the CMP signer cert I<ctx->cert> and then its chain I<ctx->chain>.
If this chain is not present in I<ctx>, it tries to build it using
I<ctx->untrusted> and caches the result in I<ctx->chain>.
Note that it will NOT add the root certificate of the chain,
 i.e, the trust anchor (unless it is part of I<ctx->extraCertsOut>).
In any case all the certificates explicitly specified to be sent out
(i.e., I<ctx->extraCertsOut>) are appended.

=head1 NOTES

CMP is defined in RFC 9810.

The I<ctx> parameter of ossl_cmp_msg_add_extraCerts()
and thus also of ossl_cmp_msg_protect() cannot be made I<const>
because I<ctx->chain> may get adapted to cache the chain of the CMP signer cert.

=head1 RETURN VALUES

ossl_cmp_calc_protection() returns the protection on success, else NULL.

All other functions return 1 on success, 0 on error.

=head1 HISTORY

The OpenSSL CMP support was added in OpenSSL 3.0.
