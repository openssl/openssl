=head1 NAME

libcmp - OpenSSL library for CMP and CRMF

=head1 SYNOPSIS

 #include <libcmp/cmp.h>
 #include <libcmp/cmp_util.h>
 #include <libcmp/crmf.h>

=head1 DESCRIPTION

libcmp provides the OpenSSL implementation of the Certificate Management
Protocol (CMP, RFC 9810) and the Certificate Request Message Format
(CRMF, RFC 4211), including client and server support and HTTP transfer.

This functionality has historically been part of libcrypto, where it is
deprecated since OpenSSL 4.1 but remains exported for ABI compatibility
until a future major release.  New code should use libcmp.

The libcmp API is declared by the headers F<< <libcmp/cmp.h> >>,
F<< <libcmp/cmp_util.h> >> and F<< <libcmp/crmf.h> >>.  They provide the
same declarations as the deprecated header locations
F<< <openssl/cmp.h> >>, F<< <openssl/cmp_util.h> >> and
F<< <openssl/crmf.h> >>, without deprecation.

=head2 Migrating from libcrypto

Code using the CMP and CRMF API of libcrypto compiles unchanged against
libcmp.  Include F<< <libcmp/cmp.h> >> instead of F<< <openssl/cmp.h> >>,
F<< <libcmp/cmp_util.h> >> instead of F<< <openssl/cmp_util.h> >>, and
F<< <libcmp/crmf.h> >> instead of F<< <openssl/crmf.h> >>, and link with
libcmp (a F<libcmp.pc> pkg-config file is installed).  A libcmp header
must be included before the corresponding deprecated header would
otherwise be reached; getting this wrong is caught with a preprocessor
error.

libcmp exports the API under symbol names of its own: the libcmp headers
map every name to the same name with a B<LIBCMP_> prefix at compile time,
so that for example B<OSSL_CMP_CTX_new> becomes B<LIBCMP_OSSL_CMP_CTX_new>.
Code built against the libcmp headers therefore requires linking with
libcmp and cannot silently keep resolving the deprecated symbols from
libcrypto, and both libraries can be loaded in one process without
interference.  The same prefix is applied to the symbols libcmp uses
internally, so that an application may link both libcmp and libcrypto
statically.  The renaming is invisible at the API level, but tools that
operate on symbol names, such as dlsym(3) or debuggers, see the
B<LIBCMP_*> names.
