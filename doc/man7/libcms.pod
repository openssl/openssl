=head1 NAME

libcms - OpenSSL library for CMS

=head1 SYNOPSIS

 #include <libcms/cms.h>

=head1 DESCRIPTION

libcms provides the OpenSSL implementation of the Cryptographic Message
Syntax (CMS, RFC 5652), including the signed, enveloped, digested,
encrypted, authenticated and compressed content types, and the S/MIME
representation of them.

This functionality has historically been part of libcrypto, where it is
deprecated since OpenSSL 4.1 but remains exported for ABI compatibility
until a future major release.  New code should use libcms.

The libcms API is declared by the header F<< <libcms/cms.h> >>.  It
provides the same declarations as the deprecated header location
F<< <openssl/cms.h> >>, without deprecation.

=head2 Migrating from libcrypto

Code using the CMS API of libcrypto compiles unchanged against libcms.
Include F<< <libcms/cms.h> >> instead of F<< <openssl/cms.h> >>, and link
with libcms (a F<libcms.pc> pkg-config file is installed).  The libcms
header must be included before the deprecated header would otherwise be
reached; getting this wrong is caught with a preprocessor error.

libcms exports the API under symbol names of its own: the libcms header
maps every name to the same name with a B<LIBCMS_> prefix at compile
time, so that for example B<CMS_sign> becomes B<LIBCMS_CMS_sign>.  Code
built against the libcms header therefore requires linking with libcms
and cannot silently keep resolving the deprecated symbols from
libcrypto, and both libraries can be loaded in one process without
interference.  The same prefix is applied to the symbols libcms uses
internally, so that an application may link both libcms and libcrypto
statically.  The renaming is invisible at the API level, but tools that
operate on symbol names, such as dlsym(3) or debuggers, see the
B<LIBCMS_*> names.

=head1 HISTORY

libcms was added in OpenSSL 4.1, at the same time as this functionality
was deprecated in libcrypto.
