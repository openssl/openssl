=head1 NAME

EVP_CIPHER-AES-CBC-HMAC-SHA-ETM - The AES-CBC-HMAC-SHA encrypt-then-MAC EVP_CIPHER implementations

=head1 DESCRIPTION

Support for AES-CBC-HMAC-SHA encrypt-then-MAC authenticated encryption using the
B<EVP_CIPHER> API.

=head2 Algorithm Names

The following algorithms are available on AArch64 platforms that support the required AES and SHA
instructions:

=over 4

=item "AES-128-CBC-HMAC-SHA1-ETM", "AES-192-CBC-HMAC-SHA1-ETM" and
"AES-256-CBC-HMAC-SHA1-ETM"

=item "AES-128-CBC-HMAC-SHA256-ETM", "AES-192-CBC-HMAC-SHA256-ETM" and
"AES-256-CBC-HMAC-SHA256-ETM"

=item "AES-128-CBC-HMAC-SHA512-ETM", "AES-192-CBC-HMAC-SHA512-ETM" and
"AES-256-CBC-HMAC-SHA512-ETM"

=back

=head2 Parameters

This implementation supports the parameters described in
L<EVP_EncryptInit(3)/PARAMETERS>.

The MAC key is set with the "mackey" parameter
(B<OSSL_CIPHER_PARAM_AEAD_MAC_KEY>) or with
B<EVP_CTRL_AEAD_SET_MAC_KEY>.

When encrypting, the tag is retrieved after finalisation with the "tag"
parameter (B<OSSL_CIPHER_PARAM_AEAD_TAG>) or with B<EVP_CTRL_AEAD_GET_TAG>.
When decrypting, the expected tag is set with the "tag" parameter or with
B<EVP_CTRL_AEAD_SET_TAG>.

Padding can be enabled or disabled with the "padding" parameter
(B<OSSL_CIPHER_PARAM_PADDING>) or with L<EVP_CIPHER_CTX_set_padding(3)>.

=head1 NOTES

These ciphers encrypt using AES-CBC and compute an HMAC over the ciphertext.
On decryption, tag verification is completed during finalisation.
Applications must not use plaintext returned by update calls until finalisation
has succeeded.

These ciphers support multiple update calls. When padding is disabled, the
total plaintext or ciphertext length must be a multiple of the AES block size
(16 bytes). When padding is enabled, standard block padding is added during
encryption and checked during decryption.

Although the underlying AES-CBC block size is 16 bytes, these implementations
report a block size based on the SHA compression block used by the stitched
implementation: 64 bytes for SHA1 and SHA256, and 128 bytes for SHA512.
Therefore B<EVP_MAX_BLOCK_LENGTH> is not a suitable maximum for these ciphers.
Applications should size output buffers using the block size returned by
L<EVP_CIPHER_get_block_size(3)> or L<EVP_CIPHER_CTX_get_block_size(3)>.
